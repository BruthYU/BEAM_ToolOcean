# Aging

The case-sensitive `Aging` category contains 12 local tools. Each accepts a
`request` object with an `operation`. Inputs and outputs are filesystem paths on
the host running ToolUniverse, not uploaded data. Each writing operation creates
a new result directory. Large matrices are returned as artifact descriptors.

## Tools

| Tool | Operations |
|---|---|
| AgingIO | inspect_dataset, import_expression, attach_metadata, export_results |
| AgingPreprocess | filter_qc, align_gene_ids, normalize_expression, prepare_model_input |
| AgingPseudobulk | aggregate_counts, summarize_cell_counts |
| RNAAgeCalc | predict_age |
| scAgeClock | prepare_input, predict_age |
| SenCID | score_senescence |
| AgingJointSummary | join_model_results, summarize_by_donor, summarize_by_cell_type |
| AgingAssociation | compare_groups, analyze_age_association, analyze_paired_change, compare_model_readouts |
| AgingComposition | summarize_proportions, test_composition_changes, assess_composition_sensitivity |
| AgingDifferentialExpression | compare_groups, associate_with_score, analyze_paired_change |
| AgingPathway | run_preranked_gsea, run_overrepresentation, score_gene_sets |
| AgingValidation | evaluate_age_prediction, validate_external_cohort, assess_robustness, evaluate_perturbation |

`AgingCandidatePrioritization` is not part of this P0 implementation.

## Loading and calling

```python
from tooluniverse import ToolUniverse

tu = ToolUniverse(load_workspace=False)
try:
    tu.load_tools(categories=["Aging"], clear_existing=True)
    result = tu.run_one_function({
        "name": "AgingPseudobulk",
        "arguments": {"request": {
            "operation": "aggregate_counts",
            "input_path": "/data/cells.h5ad",
            "output_dir": "/data/aging-results",
            "donor_key": "donor_id",
            "sample_key": "sample_id",
            "cell_type_key": "cell_type",
            "metadata_columns": ["group", "age"],
            "min_cells": 10,
        }},
    })
finally:
    tu.close()
```

The complete parameter contract is in `src/tooluniverse/data/aging_tools.json`.
The `schema_*.json` files are editable fragments; run `assemble_schema.py` after
changes. The data fragment is generated by `build_data_schema.py`.

## Data contract

* CSV expression defaults to observations (samples/cells) in rows and genes in
  columns, with observation IDs in the first column. `AgingIO.import_expression`
  also accepts genes-by-observations via an explicit orientation.
* h5ad matrices follow AnnData observations × genes. `layer` selects a matrix;
  raw counts are required for QC, aggregation and differential expression.
* Record `species`, `tissue`, `gene_id_type`, `expression_scale` and `data_kind`
  at import. Values are supplied by the caller, not inferred from filenames.
* Metadata joins use exact IDs, preserve leading zeroes and reject ambiguous
  duplicates. Multiple samples from the same donor need an explicit sample key.
* Pseudobulk groups by donor, sample and cell type. Its metadata must be constant
  within each group. It sums counts without normalization. It is a DE input, not
  automatically a valid input to a bulk-trained aging clock.
* Model-specific preprocessing branches preserve raw source files. Initial model
  adapters support human data; no implicit ortholog mapping is performed.

## Model adapters

Inference uses published weights/coefficients, not synthetic replacement models.
Model bundles are prepared separately using `prepare_model_bundles.py`; they
contain source information, file checksums and matching feature metadata. Only
use trusted bundles: published sklearn models use pickle/joblib serialization,
and the scAgeClock bundle includes its upstream architecture source.

* **RNAAgeCalc** evaluates official exported elastic-net coefficients on
  `log2(FPKM + 1)`. Counts require gene lengths in bases. The initial portable
  backend requires complete model-gene coverage and does not reproduce the R
  package's KNN imputation for missing genes. A bundle identifies a fixed tissue
  and signature. This backend does not require R at inference time.
* **scAgeClock** uses the official GMA architecture and checkpoint, with explicit
  feature order and categorical indices. `prepare_input` converts raw counts
  using the bundle's features and category mapping; `predict_age` performs
  batched inference with explicit `device="cpu"` or `"cuda"`. Metadata labels
  must match the official vocabulary or be supplied as validated indices.
  Prepare comparison groups together or pass the same explicit `target_sum`
  across batches: the default target is the cohort median library size.
* **SenCID** uses official SVM and logistic classifiers and the published
  non-denoising preprocessing. Optional DCA denoising is not implemented, so
  TensorFlow is not required. Scores are SID-specific, not predicted ages.
  Low gene coverage is rejected rather than silently treated as complete data.

Upstream projects: [RNAAgeCalc](https://github.com/reese3928/RNAAgeCalc),
[scAgeClock](https://github.com/gangcai/scageclock),
[SenCID](https://github.com/JackieHanLab/SenCID).
Their code/model licenses remain applicable (GPL-2, BSD-3-Clause and MIT,
respectively; inspect downloaded bundles and upstream licensing for artifacts).

## Serial analysis

1. Import, annotate and inspect data; apply QC while retaining counts.
2. Prepare independent model inputs and run applicable models. Bulk and
   single-cell clocks are complementary branches, not model-to-model inputs.
3. Join results at a common grain (cell, sample or donor) using explicit keys.
   Keep age predictions and each SID as separate readouts. Aggregate cell
   results by donor and cell type before group inference.
4. Compute cell proportions from all relevant cell types. Group comparisons
   use donor-level OLS with HC3 standard errors and t intervals. Composition
   tests are exploratory marginal proportion analyses, not a compositional
   generative model. Composition sensitivity is not causal mediation.
5. Aggregate counts to pseudobulk, then select one cell type using DE's
   `cell_type`/`cell_type_key`. Fit PyDESeq2 negative-binomial models on biological
   replicates, with group, continuous score or donor-paired designs. Output
   includes log2 fold changes, Wald intervals, P values, adjusted P values and
   reasons for filtered genes.
6. Pass DE's `results.path` into local-GMT/explicit-gene-set GSEA. ORA requires
   an explicit measured/tested gene background. Gene-set scoring requires
   `expression_scale="log_normalized"`; use `AgingPreprocess.normalize_expression`
   to produce a separate log-normalized layer from counts. These scores are descriptive.
7. Evaluate chronological age prediction, compare matched hypotheses across
   independently analysed cohorts, or assess leave-one-donor-out sensitivity.
   External-cohort comparison does not itself establish independence of cohorts.

Zero-residual-variance, confounded and insufficient-replicate designs fail with
an explanatory error instead of an invented significance value. Associations
with expression-derived age/SID scores are exploratory and can reuse the same
genes; use independent data or perturbation evidence for mechanism validation.
A reduced predicted age or SID score is not evidence of longer lifespan.

## Runtime and testing

Development machines prepare source/dependencies and download data. Run analysis
on a cluster worker with `slime:v0`, following the repository's
`skills-cluster/toolocean-gpu-replay` workflow. The isolated Aging environment is
`/opt/aging-venv`; it uses the existing `/opt/toolocean-venv` dependencies and the
base image's PyTorch. Added packages include PyDESeq2, GSEApy and rdata (bundle
preparation only). No runtime network access is required.

```bash
PYTHONPATH=/path/to/BEAM_ToolOcean/ToolUniverse/src \
/opt/aging-venv/bin/python -m pytest -q -o addopts= \
  tests/unit/test_aging_data.py tests/unit/test_aging_models.py \
  tests/unit/test_aging_statistics.py tests/unit/test_aging_mechanism.py \
  tests/integration/test_aging_category.py
```

Synthetic count fixtures exercise conservation, ID alignment, donor designs and
serial DE/pathway operations. Model smoke tests use separately downloaded
upstream examples and real model weights; these engineering checks do not
constitute biological validation of an intervention.

### Reproduce this deployment

From the networked development host, `download_models.py --output DIR` fetches
only the reviewed URLs and verifies SHA-256 checksums from `model_sources.json`.
On the compute worker, run `prepare_model_bundles.py --upstream DIR --output DIR`
to create the three deployable bundles and small author-provided fixtures.
See [models.md](models.md) for exact model input requirements and limitations.

For the current GPFS project, `cluster-runtime/aging/models` already contains the
prepared bundles. `submit_cluster_validation.sh PROJECT OUTPUT` submits a fresh
GPU worker; set `IMAGE` to the digest in `validation.json` to avoid stale mutable
tag caches. `validate_worker.sh` checks installed source hashes, runs the three
models through the SDK, checks reference numerical agreement, and runs the
complete tests. Use a new output directory for each run.

Dependencies added to the existing image are pinned in `requirements.txt`.
The runtime interpreter is `/opt/aging-venv/bin/python`; default system Python is
unchanged. Models and test data remain on GPFS and are not baked into the image.
